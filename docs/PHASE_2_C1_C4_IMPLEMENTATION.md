# AMAN.C — تنفيذ المرحلة الثانية (C1–C4) — سجل الدفعة الأولى

> **تحديث الحالة:** هذا تقرير الدفعة C1–C4 فقط. أُنجزت لاحقًا C5–C8، والتقرير الأشمل والأحدث هو [PHASE_2_C1_C8_IMPLEMENTATION.md](./PHASE_2_C1_C8_IMPLEMENTATION.md).

**الفرع:** `feature/phase-1-app-shell`  
**النطاق:** واجهات العميل C1 إلى C4  
**الحالة:** نُفذت دفعة الواجهات والتفاعلات الأساسية ورُفعت إلى الفرع. لم تُدمج في `main` ولم تُنشر.

## C1 — الرئيسية والبحث
- الإبقاء على شريط التطبيق العلوي والسفلي الذي أُنجز في المرحلة الأولى.
- تطوير حالة البحث والتحقق الأولي من وجود رقم وطول إدخال معقول، وتطبيع الأرقام العربية والفارسية إلى صيغة رقمية.
- إظهار حالة تحميل مؤقتة ثم خطأ اتصال واضح عند غياب خدمة البحث.
- عدم الادعاء بصحة بادئة أو شركة أو نتيجة بحث دون بيانات الشركات والخادم.
- البحث لا يضيف الرقم إلى قائمة العميل.
- دعم استقبال نتيجة بحث موثوقة لاحقًا وفتح تفاصيلها مع الاحتفاظ بمصدر الرجوع.

## C2 — الأرقام
- إنشاء منطقة بحث ضمن أرقام الحساب.
- إضافة تصفية حسب شركة الاتصالات الموجودة في البيانات فقط.
- إضافة تصفية حالة الحماية: محمي، غير نشط، منتهي-مصادر.
- إنشاء بطاقات رقم تفتح تفاصيل الرقم.
- حالات القائمة الفارغة وعدم وجود نتائج مطابقة.
- عرض أرقام فعلية فقط عند تمريرها إلى واجهة البيانات؛ لا توجد بيانات تجريبية.

## C3 — تفاصيل الرقم
- بناء نافذة تفاصيل موحدة يمكن فتحها من الرئيسية أو قائمة الأرقام.
- دعم نماذج الحالات الخمس: غير مشترك، محمي لدى العميل نفسه، محمي لدى عميل آخر، غير نشط ضمن مهلة التنشيط، ومنتهي-مصادر.
- عرض بيانات الباقة والفترة والتواريخ فقط عندما تصل من مصدر موثوق.
- إخفاء أي تفاصيل تخص العميل الآخر، والاكتفاء برسالة الخصوصية.
- عرض الإجراء الموافق للحالة فقط، مع توضيح أن إنشاء الطلب أو البلاغ غير متاح قبل ربط الخدمة الخلفية.
- لا يُعرض إجراء تنشيط لحالة منتهي-مصادر.

## C4 — العمليات وتفاصيل العملية
- إنشاء قائمة عمليات العميل.
- إضافة البحث برقم الهاتف أو رقم الطلب.
- تصفية حالات الطلب الثلاث: قيد المراجعة، معتمد، مرفوض.
- إنشاء بطاقات عمليات ونافذة تفاصيل للقراءة فقط.
- تضمين نوع العملية والرقم والشركة والباقة والمدة والسعر ووسيلة الدفع ومرجع الدفع والتاريخ والحالة وسبب الرفض عند توفره.
- حالات القائمة الفارغة وعدم وجود نتائج مطابقة.

## واجهة تمرير البيانات
أضيفت واجهة داخلية `window.AMANClientData` لتمرير سجلات حقيقية إلى واجهة العميل:
- `setNumbers(items)`
- `setOperations(items)`
- `openNumberDetails(number, source)`
- `showSearchResult(number)`
- `openOperationDetails(operation)`

هذه الواجهة لا تتصل بقاعدة البيانات بذاتها ولا تنشئ بيانات؛ إنها نقطة ربط واجهة فقط.

## قيود لم تُدّعَ كإنجاز
- خدمة البحث الفعلية غير مربوطة.
- بيانات الشركات والبادئات غير مربوطة؛ لذلك لا يمكن اعتماد صحة الشركة أو البادئة محليًا.
- قاعدة بيانات العميل والمصادقة والطلبات والدفع غير مربوطة.
- أزرار الاشتراك والتمديد والتنشيط والبلاغ لا تنشئ طلبات حقيقية؛ تعرض سبب عدم الإتاحة.
- لا توجد بيانات حقيقية متاحة للقوائم حتى ربط الخدمات.
- لم تُنشأ قاعدة بيانات فعلية أو تُطبق ترحيلات أو تُستخدم أسرار.
- لم يُعدل `main` ولم يحدث دمج أو نشر.

## التحقق المنفذ
- فحص صياغة JavaScript للعميل باستخدام محلل JavaScript: **PASS**.
- مطابقة جميع استدعاءات `getElementById` في ملف العميل مع معرفات HTML: **PASS**، دون معرفات مفقودة.
- فحص وجود أدوات تصفية C2 ونافذة تفاصيل C4: **PASS**.
- لم تُشغّل `node scripts/validate.mjs` أو اختبارات المتصفح من بيئة تشغيل كاملة في هذه الدفعة.
- سير العمل الحالي في GitHub لا يبدأ عند الدفع إلى هذا الفرع؛ فهو يستهدف `feature/real-product-foundation` للدفع المباشر وطلبات الدمج إلى `main`.
