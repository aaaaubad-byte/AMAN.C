# AMAN.C — المرحلة الثالثة: الإدارة A1–A4

**فرع التنفيذ:** `feature/phase-3-admin-a1-a4`  
**النطاق:** A1 تسجيل دخول الإدارة، A2 الرئيسية، A3 قائمة الطلبات، A4 تفاصيل الطلب.

## A1 — تسجيل دخول الإدارة
- جعل شاشة الدخول هي الوجهة الافتراضية؛ لا تظهر لوحة الإدارة قبل التحقق من جلسة مدير.
- واجهات تكامل لخدمات `getCurrentAdmin` و`signInAdmin` و`signOutAdmin`.
- لا يُقبل الدخول إلا برد موثوق يثبت `admin.is_admin === true`.
- لا توجد جلسة وهمية ولا اعتماد على اختيار دور من الواجهة.

## A2 — الرئيسية
- مؤشرات الطلبات قيد المراجعة، الأرقام المحمية، البلاغات المفتوحة، مهام السداد المستحقة، العملاء، والإيرادات المعتمدة.
- تحميل المؤشرات عبر `getDashboardSummary` فقط، مع زر تحديث.
- عند غياب الخدمة تبقى القيم غير متاحة ولا تُعرض أرقام مختلقة.
- روابط الأقسام الحالية محفوظة؛ الأقسام خارج نطاق A1–A4 تبقى مؤجلة.

## A3 — الطلبات
- قائمة الطلبات مع بحث ومرشحات حالة الطلب ونوع العملية والشركة.
- الحالة الافتراضية «قيد المراجعة».
- فتح تفاصيل الطلب مع الاحتفاظ بمسار الرجوع.
- بطاقات الطلبات تُبنى بعناصر DOM ونصوص آمنة بدل إدخال بيانات الخادم كـ HTML.

## A4 — تفاصيل الطلب
- عرض بيانات الطلب والعميل والرقم والفترة الحالية ومرجع الدفع.
- عرض التحذيرات التي يعيدها الخادم فقط.
- معاينة أثر الاعتماد من `getApprovalPreview` قبل إرسال قرار الاعتماد.
- قائمة أسباب الرفض تأتي من `getRejectReasons` ولا تُخترع محليًا.
- تنفيذ القرار لا يُعلن نجاحه إلا بعد تأكيد صريح من الخدمة؛ الطلبات المعتمدة أو المرفوضة للقراءة فقط.

## عقود الخدمات الخلفية المطلوبة
`getCurrentAdmin`, `signInAdmin`, `signOutAdmin`, `getDashboardSummary`, `listRequests`, `getRequestDetails`, `getApprovalPreview`, `getRejectReasons`, `approveRequest`, `rejectRequest`.

## حدود هذه الدفعة
هذه الدفعة تنفذ واجهات الإدارة وتكاملاتها الأمامية فقط. لا يوجد اتصال فعلي بخدمة مصادقة أو قاعدة بيانات أو صلاحيات خادمية حتى الآن. يجب فرض صلاحيات المدير، والتحقق من حالة الطلب وملكية الرقم وتكرار مرجع الدفع، وتنفيذ الاعتماد/الرفض بصورة ذرية في الخادم. لم تُنشأ بيانات وهمية أو أسرار أو قاعدة بيانات فعلية، ولم تُطبق migrations.

## ما لم يدخل في هذه الدفعة
A5/A6 نوافذ القرار المستقلة وA7/A8 إدارة الأرقام وتفاصيلها نُفذت لاحقًا في `docs/PHASE_3_A5_A8_IMPLEMENTATION.md`. تبقى A9 وما بعدها مراحل لاحقة.

## التحقق
يجب اعتبار اكتمال هذه الدفعة واجهيًا فقط إلى أن تنجح اختبارات GitHub Actions وفحوص المتصفح، ثم تُختبر الخدمات الخلفية عند ربطها. لا يُعد وجود عناصر الواجهة دليلًا على اكتمال الوظائف التشغيلية.
