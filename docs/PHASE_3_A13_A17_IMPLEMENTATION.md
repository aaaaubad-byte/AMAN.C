# تقرير تنفيذ المرحلة الثالثة — A13 إلى A17

الفرع: `feature/phase-3-admin-a9-a12-v2`

## النطاق
- A13 تفاصيل مهمة السداد: الرقم، الشركة، الاستحقاق، الحالة، وقت التنفيذ، وسياق الحماية. الإجراءات تظهر وفق حالة المهمة.
- A14 تأكيد التنفيذ: نافذة تأكيد مستقلة، وتحديث الحالة ووقت التنفيذ فقط بعد استجابة نجاح الخدمة. يمنع تكرار التنفيذ في المحاكي.
- A15 إعادة الجدولة: اختيار موعد جديد، معاينة عدد المهام المستقبلية غير المنفذة المتأثرة، ثم الحفظ. لا تتغير المهام المنفذة.
- A16 تقارير الإيرادات: نطاق 7/30/90/365 يومًا أو كل الفترات، عدد وإجمالي العمليات المعتمدة، وتجميع حسب نوع العملية والشركة والباقة ووسيلة الدفع، مع قائمة العمليات.
- A17 البلاغات: قائمة البلاغات وبياناتها الأساسية والتصفية حسب الحالة، وفتح عرض قراءة فقط للتفاصيل. لا حذف ولا اتخاذ قرار في A17.

## عقود الخدمات
`getTaskDetails`, `executeTask`, `previewTaskReschedule`, `rescheduleTask`, `getRevenueReport`, `listComplaints`.

## السلامة والحدود
- لا توجد قاعدة بيانات أو Backend حقيقي موصول؛ الخدمات الحالية في `?demo=1` محاكاة محلية فقط.
- يجب على الخادم الحقيقي إعادة التحقق من صلاحية المدير وحالة المهمة ومنع التكرار ذريًا وتسجيل التنفيذ الفعلي.
- إعادة الجدولة يجب أن تنفذ ذريًا على المهمة والمهام اللاحقة غير المنفذة، مع استثناء المنفذة.
- الإيرادات مشتقة من الطلبات المعتمدة فقط، وليست دليلًا على التحصيل النقدي.
- A17 قراءة فقط؛ اتخاذ قرار البلاغ وإنهاء الحماية يقع في A18 وليس ضمن هذه الدفعة.

## التحقق
تم تشغيل فحص ملفات المشروع والاختبارات الآلية عبر GitHub Actions. هذا يثبت سلامة الفحص الآلي فقط ولا يغني عن الاختبار اليدوي على المعاينة.
