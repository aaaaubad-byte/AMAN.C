# AMAN.C — تنفيذ المرحلة الثانية (C9–C12)\n\n**الفرع:** `feature/phase-1-app-shell`\n**النطاق:** استكمال أقسام العميل C9–C12 فوق C1–C8 دون استبدالها.\n\n## C9 — الحساب\n- قسم بيانات الحساب مع نموذج تحديث الاسم والبريد للعرض فقط.\n- تغيير كلمة المرور والتحقق الأولي من الحد الأدنى (4 أحرف).\n- تسجيل الخروج عبر واجهة خدمة آمنة فقط.\n- لا تدّعي الواجهة نجاحًا عند غياب الخدمة.\n\n## C10 — الإشعارات\n- قائمة الإشعارات مع تصفية الكل/المقروءة/غير المقروءة.\n- تحديث القائمة وتحديد إشعار كمقروء عبر الخدمة.\n- لا تُنشأ إشعارات تجريبية أو محلية.\n\n## C11 — تنبيهات الرقم\n- فتح إعدادات التنبيه من تفاصيل الرقم، مع تحديد الرقم المقصود.\n- تفضيلات قبل موعد السداد، قبل انتهاء الحماية، وعند تغير الحالة، وقناة داخل التطبيق/البريد.\n- القراءة والحفظ عبر خدمات خلفية فقط؛ لا يُعرض تأكيد نجاح دون رد صريح.\n\n## C12 — تقديم البلاغ\n- نموذج بلاغ يتضمن الرقم والنوع والوصف، مع تحقق إدخال أولي.\n- يدعم فتح النموذج مباشرة من تفاصيل الرقم.\n- لا يدّعي إنشاء البلاغ دون تأكيد خادم يتضمن `report_id`.\n\n## واجهات الخدمات المطلوبة\n- C9: `updateProfile`, `changePassword`, `signOut`.\n- C10: `getNotifications`, `markNotificationRead`.\n- C11: `getNumberAlertPreferences`, `updateNumberAlertPreferences`.\n- C12: `submitReport`.\n\n**حدود التنفيذ:** هذه واجهات أمامية ونقاط تكامل فقط. لا توجد مصادقة أو قاعدة بيانات أو إشعارات أو بلاغات فعلية موصولة. لم تُنشأ بيانات وهمية، ولم تُطبق migrations أو أسرار. يجب فرض الصلاحيات والتحقق من ملكية الرقم والتحقق من المدخلات في الخادم.\n\n## التحقق\n- تمت مراجعة وجود نقاط الربط في واجهة العميل. يلزم تشغيل فحص المستودع وGitHub Actions بعد الرفع؛ لا يُعلن نجاح الاختبارات قبل ظهور نتيجة فعلية.\n
