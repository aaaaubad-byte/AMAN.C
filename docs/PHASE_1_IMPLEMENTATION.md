# AMAN.C — تقرير تنفيذ المرحلة الأولى

**الفرع:** `feature/phase-1-app-shell`  
**المرحلة:** الأولى — تأسيس هيكل التطبيق والتنقل  
**الحالة:** نُفذت التعديلات ورُفعت إلى الفرع؛ لم تُدمج في `main`.

## ما نُفذ

### تطبيق العميل
- توحيد الانتقال بين الشاشات عبر دالة تنقل مركزية.
- اعتماد شريط سفلي من ثلاثة عناصر وفق مرجع العميل: الأرقام، الرئيسية، العمليات.
- نقل الوصول إلى الحساب والإشعارات إلى أيقونتين في الشريط العلوي.
- توحيد الانتقال إلى الحساب والإشعارات من الأيقونات، وإلى العمليات من روابط الخدمات.
- توفير واجهة برمجية داخلية للتنقل `window.AMANClientNavigation` وإطلاق حدث عند تغيير الشاشة.
- الإبقاء على حالة واضحة بأن البحث والمصادقة غير مرتبطين بخادم بعد.

### تطبيق الإدارة
- توحيد فتح الأقسام والعودة عبر مدير تنقل مركزي.
- حفظ مسار التنقل السابق عند الانتقال بين لوحة التحكم والأقسام وشاشة الدخول.
- إتاحة الأقسام الحالية من لوحة التحكم، مع إبقاء أقسامها في حالة عدم توفر بيانات حقيقية بدل عرض بيانات وهمية.
- توفير واجهة داخلية `window.AMANAdminNavigation` وإطلاق حدث عند تغيير القسم.

### التنسيق
- إضافة تنسيقات لأيقونات الشريط العلوي وأزرار الروابط التفاعلية والتركيز بلوحة المفاتيح.
- الحفاظ على الهوية الفاتحة والكحلية والخضراء الحالية.

## ما لم تدّعِ هذه المرحلة إنجازه
- لم تُنفذ بعد شاشات العميل التفصيلية C-01 إلى C-12 أو نماذج تفاصيل الرقم الخمسة.
- لم تُنفذ شاشات الإدارة التفصيلية A-01 إلى A-31.
- لم تُربط المصادقة أو قاعدة البيانات أو البحث أو الطلبات أو المهام.
- لم تُنشأ بيانات تجريبية على أنها بيانات حقيقية.
- لم يُعدل مخطط Supabase أو تُطبق أي ترحيلات.
- لم يُعدل `main` ولم يحدث دمج أو نشر.

## الفحص
- أُجري فحص اتساق ساكن أثناء التعديل ومراجعة وصلات التنقل ومعرّفات عناصر الواجهة.
- يجب تشغيل `node scripts/validate.mjs` واختبارات التصفح الفعلية على نسخة الفرع قبل اعتبار المرحلة متحققة بالكامل.
- لم يُشغّل GitHub Actions لهذه الدفعة؛ إعداد التحقق الحالي لا يستهدف هذا الفرع عند الدفع المباشر.

## نقطة التسليم للمرحلة الثانية
بعد مراجعة معاينة المرحلة الأولى، تبدأ المرحلة الثانية بتطوير واجهات العميل على دفعات C1–C8، مع الالتزام بمرجع العميل المبسّط الأحدث وعدم إدخال منطق أو بيانات غير معتمدة.
