# AMAN.C — تنفيذ المرحلة الثانية (C1–C8)

**الفرع:** `feature/phase-1-app-shell`  
**النطاق:** واجهات العميل C1 إلى C8  
**الحالة:** تنفيذ واجهات وتفاعلات C1–C8 ورُفع إلى فرع التطوير. لم تُدمج في `main` ولم تُنشر.

## C1 — الرئيسية والبحث
- البحث مع تطبيع الأرقام العربية والفارسية والتحقق الأولي من وجود رقم وطول إدخال معقول.
- عرض التحميل ثم خطأ اتصال واضح عند غياب خدمة البحث.
- لا يدّعي التطبيق صحة بادئة أو شركة أو نتيجة دون مصدر بيانات موثوق، ولا يضيف الرقم إلى قائمة العميل عند البحث.
- نقطة استقبال نتيجة بحث موثوقة متاحة عبر `AMANClientData.showSearchResult(number)`.

## C2 — الأرقام
- بحث ضمن أرقام العميل وتصفية الشركة من البيانات المتاحة وحالة الحماية.
- بطاقات تفتح تفاصيل الرقم، مع حالات القائمة الفارغة وعدم وجود نتائج.
- لا تعرض القائمة إلا سجلات تمررها طبقة البيانات الفعلية.

## C3 — تفاصيل الرقم
- نافذة موحدة لنماذج الرقم الخمسة: غير مشترك، محمي لدى العميل نفسه، محمي لدى عميل آخر، غير نشط ضمن مهلة التنشيط، ومنتهي-مصادر.
- تعرض البيانات المتاحة فقط؛ لا تكشف معلومات العميل الآخر.
- الإجراء يتحدد بحسب الحالة: اشتراك أو تمديد أو تنشيط أو بلاغ، ولا يظهر التنشيط للرقم منتهي-مصادر.
- حفظ سياق الرقم عند الدخول إلى مسار الحماية والعودة إليه.

## C4 — العمليات
- قائمة طلبات العميل والبحث بالرقم أو رقم الطلب والتصفية بحالة الطلب.
- بطاقات تعرض نوع العملية والرقم والتاريخ والحالة والمبلغ عند توفره.

## C5 — تفاصيل العملية
- شاشة تفاصيل مستقلة بدل الاكتفاء ببطاقة القائمة.
- تعرض رقم الطلب ونوع العملية والرقم والشركة والباقة والمدة والسعر ووسيلة الدفع ومرجع الدفع والتاريخ والحالة وسبب الرفض عند توفره.
- أزرار نسخ رقم الطلب ومرجع الدفع عند توفرهما.
- قراءة فقط؛ لا إجراءات إدارية في واجهة العميل.
- الرجوع إلى قائمة العمليات مع حفظ السياق.

## C6 — الحماية
- شاشة إنشاء طلب الحماية تستقبل الرقم والشركة ونوع العملية تلقائيًا من تفاصيل الرقم.
- لا يختار العميل نوع العملية يدويًا؛ يجري التحقق من توافق العملية مع حالة الرقم.
- قوائم الباقات تُقبل فقط من مصدر بيانات يمرر سجلات مفعّلة ومطابقة للشركة ونوع العملية، وبمدة وسعر رقميين صالحين.
- وسائل الدفع والتعليمات تُعرض من البيانات المعتمدة فقط.
- يتطلب النموذج اختيار باقة ووسيلة دفع وإدخال مرجع الدفع.
- لا توجد باقات أو وسائل دفع افتراضية أو مخترعة.
- زر الرجوع يعيد إلى تفاصيل الرقم ذاتها.

## C7 — مراجعة العملية
- شاشة مراجعة تعرض الرقم والشركة ونوع العملية والباقة والمدة والسعر ووسيلة الدفع ومرجع الدفع.
- الرجوع يعيد إلى نموذج الحماية مع الاحتفاظ بالمدخلات.
- يمنع تكرار الإرسال أثناء وجود طلب جارٍ.
- لا يرسل الطلب ما لم تتوفر خدمة خلفية آمنة عبر واجهة الخدمة المحددة.

## C8 — نتيجة الإرسال
- شاشة نتيجة منفصلة.
- لا تعرض النجاح إلا إذا أعادت خدمة الخادم `success: true` ومعرّف طلب.
- النجاح المؤكد يعرض حالة «قيد المراجعة» ورقم الطلب، مع توضيح أن الإرسال لا يبدأ الحماية.
- عند غياب الخدمة أو فشل الاتصال لا تدّعي إنشاء الطلب أو فشله قطعًا؛ تطلب التحقق من قائمة العمليات قبل إعادة المحاولة لتجنب التكرار.
- أزرار الانتقال إلى العمليات أو العودة إلى تفاصيل الرقم.

## واجهات الربط التي تنتظر الخدمات الخلفية
- `window.AMANClientData.setNumbers(items)`
- `window.AMANClientData.setOperations(items)`
- `window.AMANClientData.setProtectionCatalog(packages, paymentMethods)`
- `window.AMANClientData.showSearchResult(number)`
- `window.AMANClientData.openNumberDetails(number, source)`
- خدمة الإرسال المتوقعة: `window.AMANClientServices.submitProtectionRequest(payload)`

هذه واجهات ربط للواجهة فقط. لم يتم إنشاء اتصال فعلي بقاعدة البيانات أو خدمة البحث أو المصادقة أو الطلبات. يجب أن تتحقق طبقة الخادم من المستخدم والصلاحية وحالة الرقم والباقة والسعر ومرجع الدفع وتمنع التكرار ذريًا. لا يُعتمد على تحقق المتصفح في أي قرار أمني أو مالي.

## قيود لم تُدّعَ كإنجاز
- البحث الفعلي والمصادقة وقاعدة البيانات وخدمة إنشاء الطلب غير مربوطة.
- لا توجد بيانات باقات أو وسائل دفع حقيقية متاحة في الواجهة حتى تمريرها من خدمة معتمدة.
- أزرار إرسال الطلب لا تنشئ طلبًا دون خدمة خلفية.
- لم تُنشأ قاعدة بيانات فعلية ولم تُطبق migrations ولم تُستخدم أسرار.
- لم يُعدل `main` ولم يحدث دمج أو نشر.

## التحقق
- فحص صياغة JavaScript باستخدام محلل JavaScript: **PASS**.
- فحص مطابقة معرفات DOM مع استدعاءات `getElementById`: جارٍ/يُسجل في تسليم الدفعة بعد إعادة التحقق النهائية.
- لم تُشغّل اختبارات المتصفح أو `scripts/validate.mjs` في بيئة كاملة؛ سير العمل الحالي لا يبدأ عند الدفع إلى هذا الفرع.
- لا توجد ادعاءات بأن الاختبارات الكاملة نجحت.
