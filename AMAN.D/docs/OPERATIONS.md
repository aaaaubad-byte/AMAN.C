# التشغيل والعمليات

## قاعدة البيانات

يستخدم AMAN.D مشروع Supabase الحالي نفسه الذي يستخدمه AMAN.C. لا تنشئ مشروعًا أو قاعدة بديلة عند تشغيل التطبيق. تضبط `shared/config.js` عنوان المشروع ومفتاح النشر العام فقط؛ لا يوضع مفتاح service_role أو أي مفتاح سري داخل ملفات الواجهة.

## المصادقة والجلسات

تستخدم المصادقة Supabase Auth. يحتفظ المحوّل بمفاتيح الجلسات القديمة لضمان توافق الجلسات الحالية:

- `aman_c_client_auth`
- `aman_c_admin_auth`
- `aman_c_admin_remember`

يُستخدم خيار «تذكرني» لتحديد مدة/موضع حفظ جلسة الإدارة وفق منطق المحوّل. لا تغيّر أسماء المفاتيح دون خطة انتقال معتمدة.

## البناء

1. تأكد من وجود أصول P-01 الثنائية المطلوبة.
2. شغّل `npm run validate`.
3. شغّل الاختبارات بعد اعتماد مرحلة الاختبارات.
4. شغّل `npm run build` لإنتاج `dist/`.
5. يمكن تشغيل `npm run serve` لعرض النسخة المبنية محليًا.

يحتوي `dist/` على صفحات العميل والإدارة والملفات المشتركة والأنماط والأصول فقط. يختم البناء معرّف الإصدار في عاملي الخدمة.

## PWA والتخزين المؤقت

لكل تطبيق manifest وService Worker مستقلان. يقتصر التخزين المؤقت على موارد ثابتة مسموح بها، ولا تُخزّن استجابات خاصة أو استجابات تحمل بيانات اعتماد أو ترويسات تمنع التخزين.

## النشر

`deploy/pages.yml` قالب يدوي محفوظ خارج مجلد GitHub Actions. هو غير مفعّل ولا ينفذ أي نشر. لا تنقله إلى `.github/workflows` ولا تنشر التطبيق قبل اكتمال الاختبارات والمراجعة والموافقة الصريحة.

## الترحيلات

ملفات `supabase/migrations/` نسخ حرفية من تاريخ قاعدة البيانات الحالية. لا تطبقها على قاعدة الإنتاج؛ وجودها داخل المستودع لا يعني أن هناك ترقية مطلوبة.
