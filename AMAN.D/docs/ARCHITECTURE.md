# البنية المعمارية لـ AMAN.D

## الغرض

AMAN.D هو التطبيق الجديد المستقل للعميل والإدارة. يعمل وقت التشغيل من الملفات الموجودة داخل مجلد AMAN.D، ويتصل بقاعدة Supabase الحالية نفسها عبر واجهة الخدمات المشتركة. لا يعتمد وقت التشغيل أو البناء على AMAN.C أو AMAN.B.

## المكونات

| المكوّن | المسؤولية |
|---|---|
| `client/` | واجهة العميل، المصادقة، البحث، الأرقام والعمليات والإشعارات والبلاغات والحساب |
| `admin/` | واجهة المدير، مراجعة الطلبات، الأرقام والعملاء والمهام والتقارير والإعدادات |
| `shared/config.js` | عنوان مشروع Supabase ومفتاح النشر العام |
| `shared/runtime.js` | تعريف عقود العميل والإدارة وتوحيد النتائج وتسجيل المحوّل |
| `shared/supabase-adapter.js` | تنفيذ العقود عبر Supabase Auth وRPC |
| `shared/theme.js` و`shared/ui-icons.js` | السمة والطبقة البصرية والأيقونات |
| `styles/` | الأنماط الأساسية والطبقة البصرية وأنماط دخول الإدارة |
| `assets/` | أصول الهوية والأيقونات |
| `supabase/migrations/` | نسخ مرجعية حرفية من تاريخ مخطط قاعدة البيانات الحالي |
| `scripts/` | التحقق والبناء والخادم الثابت |
| `tests/` | اختبارات العقود والاستقلال والواجهة وPWA |
| `deploy/` | قالب نشر يدوي غير مفعّل |

## مسار البيانات

```text
واجهة العميل أو الإدارة
        ↓
AMANClientServices / AMANAdminServices
        ↓
shared/runtime.js
        ↓
shared/supabase-adapter.js
        ↓
Supabase Auth + RPC
        ↓
قاعدة AMAN.C الحالية
```

لا تستعلم الواجهات من الجداول مباشرة. تُنفّذ عمليات القراءة والكتابة عبر عقود الخدمة، وتبقى صلاحيات البيانات والتحقق النهائي في قاعدة البيانات.

## ترتيب التحميل

تحمّل كل واجهة طبقة التشغيل المشتركة أولًا، ثم مكتبة Supabase، ثم الإعدادات والمحوّل، ثم ملفات الواجهة. تُحمّل وحدات الإدارة بعد نواة الإدارة وبالترتيب المحدد في `admin/index.html`. يحمّل `theme.js` الطبقة البصرية والأيقونات بعد تهيئة المستند.

## الاستقلال

- لا يُحمّل أي ملف تشغيل من AMAN.C أو AMAN.B.
- لا توجد طبقة محاكاة أو بيانات افتراضية ناجحة.
- عند غياب المحوّل، تعيد طبقة التشغيل خطأ `service_not_configured` ولا تصطنع بيانات.
- ملفات البناء المنشورة هي ملفات التشغيل فقط؛ لا تُضمّن الاختبارات أو وثائق AMAN.B.
- لكل تطبيق Service Worker ونطاق تخزين مؤقت مستقلان.

## حدود التنفيذ

لا يتضمن هذا التصميم اتصالًا مباشرًا بشركات الاتصالات أو تنفيذًا آليًا خارج خدمات Supabase المتاحة. كما أن وجود ملفات الترحيل لا يعني تطبيقها على قاعدة الإنتاج.
