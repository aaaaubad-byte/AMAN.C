# AMAN.D

مشروع مستقل لإعادة بناء تطبيق أمان داخل هذا المستودع.

## مبدأ الاستقلال

- جميع ملفات التطبيق وإعداداته واختباراته ووثائقه وأصوله الخاصة توضع داخل هذا المجلد.
- لا يعتمد التشغيل أو البناء على ملفات التطبيق الموجودة خارج `AMAN.D/`.
- لا يستورد أي ملف من AMAN.C أو AMAN.B أو من جذر المستودع.
- يمكن قراءة ملفات المصدر المعتمدة خارج المجلد لاستخلاص السلوك والعقود والأصول فقط، ثم إنشاء نسخة مستقلة داخل AMAN.D.
- لا تُنقل المحاكاة أو منطقها أو أدواتها.
- لا أسرار أو مفاتيح إدارية داخل ملفات الواجهة؛ إعداد Supabase يقتصر على عنوان المشروع والمفتاح العام المخصص للنشر.
- لا تغيير على قاعدة الإنتاج، ولا نشر أو دمج دون موافقة مستقلة.

## قواعد التنفيذ

1. المصدر المرجعي لسلوك التطبيق والقرارات المعتمدة هو ما ثُبّت في وثائق التجهيز، مع أولوية القرار الأحدث عند التعارض.
2. قراءة المصدر الكامل واعتمادياته قبل إنشاء كل ملف.
3. كتابة الملفات ملفًا ملفًا: تحديد المسؤولية والعقد، مقارنة المصدر، تنفيذ مستقل، اختبار متاح، ثم توثيق النتيجة.
4. لا تغيير للسلوك التجاري أو قواعد المهام أو المصادقة بالاجتهاد؛ أي فجوة غير محسومة تُسجل وتُرفع قبل تنفيذها.
5. لوحة تفاصيل الرقم كما في المصدر المعتمد، ولا يُنقل `#operation-sheet` القديم غير المستخدم.
6. تبقى الإدارة مقسمة حسب النطاق، مع ترتيب تحميل صريح، وتملك كل وحدة أحداثها دون التقاط عام يخفي سلوكًا آخر.
7. لا محاكاة ولا وضع تجريبي يغيّر منطق التطبيق أو يحقن بيانات.
8. ترحيلات Supabase الستة تُنسخ لاحقًا حرفيًا من المصدر الحي `statements[1]` وبالأسماء والبصمات المثبتة في تقرير التدقيق؛ لا تُطبق على الإنتاج.
9. اختبارات القواعد الديناميكية تحتاج بيئة تطوير مستقلة وموافقة منفصلة؛ لا تختبر الإنتاج.
10. كل مسارات البناء والتشغيل والتحقق داخل هذا المجلد، وتُختبر استقلالية المشروع من الملفات الخارجية.

## الحالة

- تم إنشاء مجلدات الهيكل الأولي.
- لم يبدأ بعد إنشاء ملفات التطبيق أو نقل الأصول أو نسخ ترحيلات SQL.
- المرجع التفصيلي للشجرة: `AMAN.B/04-FILE-TREE-PROPOSED.md` في مرحلة التجهيز؛ لا يكون هذا المرجع اعتماد تشغيل لـ AMAN.D.
